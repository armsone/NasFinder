# Mac MP3 inline playback fix (2.13.1 / 202610171625)

- Time: 2026-10-17 16:2x KST, agent: Claude Sonnet 5.5
- Cause (read-only header check of the exact file): RIFF/WAVE, `fmt ` tag 0x0055 (MPEG Layer 3), 44100Hz stereo, `data` chunk starts with MPEG sync FFFB. AVAudioPlayer/AVURLAsset reject this wrapper (WAVEAudioFile::OpenFromDataSource failed), and the loader then marked the file permanently unusable.
- Fix:
  - `WAVEMPEGUnwrapper` (TrailerMusic.swift): validates RIFF/WAVE, chunk bounds/padding, fmt tag 0x55, MP3 sync/ID3 at data start, then streams only the data chunk into a new `.unwrapped.mp3` beside the session-owned staged copy (the wrapper copy is removed). Non-matching files are left as is.
  - `TrailerMusicRemoteLoader.enforcesTrailerLimits` (false for `InlineMusicPlayback`): inline playback no longer applies the 1s–1h trailer limit nor marks files permanently unusable; the player reports open/play errors with domain/code and retry is possible. Trailer picker keeps its rules (`usableDuration` = `measuredDuration` + `validate`).
  - `TrailerMusicAuditionPlayer` is now `@MainActor`; delegate callbacks hop to the main actor via `Task { @MainActor }`, the timer uses `MainActor.assumeIsolated` (addresses the background-publish warnings).
